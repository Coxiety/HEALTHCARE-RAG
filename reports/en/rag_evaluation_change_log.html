What I changed

I added a reusable evaluator for the English pipeline so the chatbot can be scored automatically on a QA dataset with ground truth. The evaluator works at two levels:

  • Retrieval mode scores the retriever/reranker path only, using relevant document IDs when available.
  • Full mode runs the actual pipeline end to end and measures intent routing, answer quality, source coverage, and latency.

Evaluator behavior

The evaluator accepts .jsonl, .json, or .csv datasets. It normalizes a record from flexible field names so you can reuse it across different benchmark formats. 

{
  "question": "...",
  "answer": "..." | "reference_answer": "...",
  "relevant_docs": ["doc-id-1", "doc-id-2"],
  "expected_intent": "NUTRITION_LOOKUP" | "HEALTH_ADVICE" | "BOTH",
  "expected_answer_keywords": ["keyword1", "keyword2"],
  "expected_source_keywords": ["USDA", "Vinmec"]
}

The result files are always written to the output directory:

  • summary.json for aggregate metrics and run metadata.
  • cases.csv for per-question results, predictions, and scoring details.

Metrics included

Intent accuracy Retrieval hit rate Recall@k Precision@k MRR@k Answer exact match Token F1 Keyword/source hit rate Latency
Important implementation detail: the evaluator reuses the existing ENPipeline.answer() entry point conceptually, but it also exposes a retrieval-only path so retrieval quality can be measured without paying the generation cost.

How to run

Primary command documented in the README:

python main/evaluate_rag.py --input data/en/eval_200.jsonl --output-dir reports/en/rag_eval

Task added for VS Code:

  • Label: Evaluate RAG
  • Purpose: run the evaluator against data/en/eval_200.jsonl
  • Output: reports are saved to reports/en/rag_eval

Design notes

  • The input schema is intentionally flexible to support future QA benchmarks without rewriting the evaluator.
  • If relevant_docs is absent, retrieval metrics are skipped rather than failing the run.
  • If reference answers are present, answer exact match and token F1 are computed; otherwise those fields stay empty.
  • The current flow is compatible with your existing dataset at data/en/eval_200.jsonl.

Outcome

The repository now has a practical automatic evaluation path for the chatbot RAG system. You can run it from the command line or from VS Code, and the output is structured so it can be compared across model changes or dataset revisions.
